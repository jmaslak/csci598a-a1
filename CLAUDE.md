# csci598a-a1 — CaringBridge first-entry voice composer

A simulated CaringBridge journal composer: speak a first journal entry, Claude
strips the filler, you edit the draft, publishing is faked. `README.md` explains
what it does and why; this file is the orientation for working on it.

## Edit here, not there

`composer.html` is the **source of truth** — markup, CSS, and all JS in one
file. `serve/index.html` is generated by `build.py` and overwritten on every
build; never edit it.

```sh
./reload.sh          # rebuild + restart, foreground
./reload.sh -d       # detached, logs to reload.log
```

Test the recorder headlessly after touching any speech code:

```sh
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc test_recorder.js
```

`node` is broken on this machine (missing `libllhttp` dylib) — use `jsc`.

The server requires Basic auth, so manual checks need credentials:

```sh
curl -u csci598a:csci598a http://127.0.0.1:8777/
```

## The page runs in two places

`composer.html` is published as-is to a Claude Artifact **and** served locally.
`cleanUp()` and the revision path both try, in order: the artifact `sample`
capability → `POST /api/cleanup` (or `/api/revise`) → an on-device regex.
Changes must keep working in both. The artifact lives at a fixed URL — republish
to that same URL rather than creating a new one.

The local server exists because an embedded frame withholds microphone access;
that is not fixable from inside the page.

## Load-bearing details

Things that look arbitrary and are not:

- **`stopRecording` ordering.** Detach (`state.recognition`, `state.active`,
  `state.recording`) and arm `state.pendingSubmit` *before* calling `stop()`.
  `stop()` can fire `onend` synchronously, and the submit that follows re-enters
  `stopRecording`. Getting this wrong silently loses the auto-submit.
- **Only the mic button passes `{submit: true}`.** Cancel, Back, Use a sample
  and Start over must keep calling `stopRecording()` plain, or navigating away
  fires an API request.
- **One recorder, two targets.** `RECORDERS` maps a target name to element ids
  and buffer. Add capture points by adding a target — never by copying the
  recorder.
- **The subject check returns booleans, not prose.** The model reports
  `mentions_person` / `mentions_needs`; all wording lives in
  `flagMissingSubject()`. This is deliberate: the user asked that the advice
  never wander onto other topics, and a boolean cannot. It also must never
  appear inside the draft — it is a separate `<dialog>`.
- **A revision instruction is a direction, never content.** Both prompts say so
  explicitly; without it, dictated sentences get pasted into the entry.
- **`mentions_person` ignores bare first-person narration.** "I'm tired" does
  not say whose site this is. Loosening this makes the check always pass.
- **Basic auth fails closed.** Missing `BASIC_AUTH_USER`/`BASIC_AUTH_PASS` exits
  rather than serving unprotected.

## Copy rules

- It is a **first journal entry**, not an "update". Do not reintroduce update
  wording outside the sample transcript, where a speaker says it naturally.
- The page deliberately wears CaringBridge's visual identity (real tokens from
  their stylesheet) but **must not pass as the real site**: keep the demo pill,
  the footer disclaimer, and the simulated-publishing notes. Never add a
  sign-in, an account, or a lookalike domain.
- Light-only by design, matching the real site.

## Anthropic API

`server.py` calls `claude-opus-5` through `messages.parse()` with the Pydantic
`Entry` model, effort `low`. `_parse()` backs both endpoints and the `CHECKS`
string is shared by both prompts so they cannot disagree. Transcripts are not
written to disk and request logging omits bodies.

## Secrets

`.env` holds the Anthropic API key and the auth credentials. It is gitignored.
**Do not read or print it** — append with a `grep -q` guard when adding keys.
`.env.example` carries placeholders only.
